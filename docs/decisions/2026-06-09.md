2. 3일 일정

Day 1 — 기반 + API + 실기기 1회
feature/project-setup: 구조, .gitignore, requirements.txt, .env.example
feature/smartthings-client: smartthings/client.py, models.py
feature/oven-command-test: 실오븐에 모드/레시피 명령 1~2회 (AirFryer, cookRecipe 초 단위 확인)
완료 기준: PAT로 status 조회, remoteControlEnabled 확인, 명령 1회 성공

Day 2 — MCP + 핵심 Tool + 프롬프트
feature/mcp-server-skeleton: main.py, server/tools.py 뼈대
feature/prompts: server/prompts.py (모드 11종, 온도 40~200, 분→초 변환 규칙)
feature/tool-set-oven-recipe: set_oven_recipe E2E (Cursor 채팅 텍스트로 먼저 검증)
완료 기준: Cursor MCP 연결, “에어프라이 200도 25분” 텍스트 입력으로 오븐 설정

Day 3 — 음성 + 나머지 Tool + 테스트
feature/voice-input: STT → 텍스트 → (아래 파이프라인) → MCP Tool 호출
feature/tool-oven-ops: status, stop, modes, temp, time 등
feature/cook-history: SQLite 히스토리
feature/error-handling: 401, 원격제어 비활성, 검증 메시지
feature/tests: mock pytest + 실오븐 통합 테스트 스크립트/마커 분리
완료 기준: 말로 한 문장 → 오븐 동작 + mock 테스트 green + 통합 1회 pass
=> 음성 파이프라인 경로 — Cursor는 마이크 STT가 기본이 아니라서, 보통 아래 중 하나를 택하도록 선택해야한다.

방식	설명	3일 적합도
A. Voice CLI
마이크 → STT(Whisper 등) → 텍스트를 Cursor 채팅에 붙여넣기
구현 쉬움, E2E는 반쪽
B. Voice → 로컬 오케스트레이터
마이크 → STT → 같은 프로세스/스크립트에서 LLM+MCP stdio 호출
3일 목표에 가장 적합
C. Voice → MCP Tool 직접
STT 후 규칙/파서로 Tool 파라미터 추출 (LLM 없음)
빠르지만 “자연어” 품질 낮음
**이번 3일 “음성이 목표”**라면 B를 권합니다.
Cursor는 MCP 서버 개발·디버깅용, 실제 음성 데모는 voice 모듈(또는 main_voice.py)로 돌리는 식입니다.

STT 엔진도 정해야 합니다 (PRD에 없음):

openai-whisper API / 로컬 faster-whisper / Windows Speech 등
→ 한국어 “에어프라이 200도 25분” 인식 품질이 데모 성공 여부를 좌우합니다.
